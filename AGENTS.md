# AGENTS.md

MoodFlix is a single-page Streamlit app. `app.py` is the only entrypoint and contains the sidebar router plus every page; there is no `pages/` directory.

## Run and verify

- Install dependencies with `pip install -r requirements.txt` (unpinned; local environment is Python 3.13 / Streamlit 1.67).
- Run with `python -m streamlit run app.py`. Do not run `python app.py`.
- Health check: `(Invoke-WebRequest http://localhost:8501/_stcore/health).Content` should return `ok`.
- If port 8501 already returns `ok`, reuse that server. After changing `src/`, restart it; Streamlit may keep imported modules cached.
- There is no test suite, linter, typechecker, or lockfile. Syntax-check with `python -m compileall -q app.py src scripts`.
- Webcam mood detection is optional; install `requirements-vision.txt` to enable it (large TensorFlow download). Without it the Discover panel shows an install hint and everything else works.
- UI regression checks use `streamlit.testing.v1.AppTest`. The details dialog is reopened from `session_state.details_movie_id` on every script run, so its widgets appear in the AppTest tree and in-dialog posters can be clicked; YouTube embeds are read with `at.get("video")`, not `at.video`. AppTest cannot emulate the client dismissing a dialog.
- AppTest clicks widget buttons directly and does not apply CSS layout, so it can pass while an invisible poster/card overlay is broken. Verify click targets in a real browser: `document.elementFromPoint` over the poster must resolve inside the invisible overlay button (not the tile text or image), and the dialog must show Trailer/Cast.

## Architecture

- `src/data_loader.py` builds the cached catalog: it parses `year` from the trailing `(YYYY)` in the title, adds rating stats, then merges the optional `posters.csv` and `links.csv` (`imdbId`, `tmdbId`).
- Cache gotcha: `load_movies`, `load_ratings`, `load_movie_stats`, and `load_catalog` have no TTL; `load_posters` and `load_links` use 300s. Restart the server or call `st.cache_data.clear()` after editing CSVs.
- `src/recommender.py` scores with fixed weights (45% content, 20% rating quality, 10% popularity, 15% personal match, 10% mood); `randomize=True` samples from the top `n*5` pool. `refresh_queue()` in `app.py` first adds the current deck to `session_state.seen`, which enforces the no-repeat behavior.
- `src/model.py` trains a biased matrix factorisation (truncated SVD, 20 factors) on `ratings.csv` and supplies the 15% personal-match term through the `personal_scores` argument of `recommend()`. Training takes ~2.5s and is wrapped in `st.cache_data`, so restarting the server retrains; `app.py` warms it in a daemon thread at startup so the first details dialog does not pay that cost. `_collaborative_scores()` remains the fallback when no model/personal scores are passed. Metrics are computed on a per-user holdout (latest 20% by timestamp); `python scripts/evaluate_model.py` reproduces them and writes `data/model_metrics.json`. The Insights page renders the same numbers, so keep them in sync with the README table. `train()` also returns `holdout` (`actual`/`predicted` arrays for the same split); Insights plots them in the "Predicted vs actual" scatter (`model_scatter_chart()` in `app.py`, sampled to 2000 points, dashed perfect-fit line).
- `predicted_rating()` in `model.py` supplies the dialog's "★ Predicted rating" line. It blends the 25 MovieLens users with the most liked movies in common (`_taste_neighbours()`, cached on the like tuple) into `mu + item_bias + weighted latent`, and without likes it is just `mu + item_bias`. Measured on the holdout: MAE 0.826 vs 0.829 for item bias alone, so keep the "usually within about 0.8★" caveat in the UI/README and do not describe it as precise.
- Do not rank by raw latent similarity alone: it ignores quality and scores below the popularity baseline on precision@10. The evaluated and shipped blend is `0.65 * quality_prior + 0.35 * latent`, and inside `recommend()` the latent match keeps the existing 15% weight.
- Model helpers used by the UI: `taste_scores()` (0-1 match per catalog row), `taste_match()` (one movie), `ranking_scores()` (taste blended with the quality prior), `similarity_scores()` (latent similarity to one movie). `may_like_picks()` in `app.py` wraps them and excludes liked/disliked movies plus the current seed movie, but not watchlist or `seen` titles; it powers the Home row and the in-dialog "You may like" grid. Because model scores alone surface obscure low-rated titles, always route user-facing picks through `ranking_scores()`, not `taste_scores()`.
- `src/ui.py` owns all custom CSS and reusable HTML components. Poster tiles intentionally have no visible details button: each tile overlays an invisible `st.button` on the poster inside `st.container(key="mfposter_<prefix>_<id>")`, and the Discover card does the same via `clickable_movie_card()` with `key="mfcard_<prefix>_<id>"`. The CSS must absolutely position the `stElementContainer` that wraps `div.stButton` (via `:has(> div.stButton)`), not only `div.stButton`: Streamlit's button wrapper is `position: relative` and otherwise keeps the overlay in normal flow. Preserve both key prefixes, the overlay rules, and the `mf-tile`/`mf-card` styles when changing a grid.
- The theme is split: `.streamlit/config.toml` sets Streamlit colors, while gradients, cards, and button styling live in `inject_css()` in `src/ui.py`. Theme changes usually touch both. `assets/logo.jpe` is both the page icon and the sidebar image.
- The animated background is three fixed-attachment background layers on `.stApp` whose `background-position` is animated (`mf-drift`). Two things to keep in mind: positions must stay in `px`/`calc()` because percentage positions resolve against the multi-thousand-pixel page body and visibly do not move; and separate glow `<div>`s with `z-index: -1` render *behind* `.stApp`'s own background, so they are not an option. One static red layer stays put so the page never goes black mid-cycle. `prefers-reduced-motion` disables the animation.
- `src/ui.py` also provides `overview_block()` (plot paragraph), `taste_meter()` (red 0-100 bar for the model score), `movie_card()`, `clickable_movie_card()`, `poster_grid()`, `trailer_block()`, `cast_grid()`, `watch_providers_block()` (provider logo chips, styled by the `.mf-watch*` CSS), and `scroll_dialog_to_top()` (floating "↑ Top" button plus dialog scroll). When building HTML for `st.markdown`, keep each block on a single line with no blank lines: Markdown ends an HTML block at a blank line and renders the rest as a code block (this is what once broke the cast grid).
- Navigation, likes, watchlist, queue, and seen history are all session-only (`st.session_state`); there is no database or account system.

## Camera mood detection

- `src/vision.py` is optional: it imports DeepFace lazily, so the app and `requirements.txt` stay light. The camera panel on Discover checks `is_available()` (cached with `lru_cache`) and shows `INSTALL_HINT` when `requirements-vision.txt` is not installed. Do not move DeepFace into `requirements.txt` or import it at module scope. `is_available()` should check only `deepface`, not `tensorflow`: DeepFace can work even when TensorFlow is not importable as a top-level module.
- `suggest_mood()` maps the top emotion onto a mood via `EMOTION_TO_MOOD`; `Romantic`, `Nostalgic`, and `Thoughtful` do not come from faces. The manual mood radio is the source of truth: the camera only offers a `Use <mood>` button whose callback (`set_mood()`) sets `session_state.mood` and clears the queue. Never set `session_state.mood` after the radio widget is instantiated — use the callback.
- Privacy contract: the frame goes to a temp file only because DeepFace takes a path, and that file is deleted in `finally`. Nothing is uploaded, cached, or kept in `session_state`; keep it that way and keep the About/README wording accurate.
- The camera expander is open by default (`expanded=True`), so the browser shows its camera-permission prompt as soon as Discover loads. No frame is captured until the user presses Take Photo, and denying permission must leave the rest of the page working — that is why the copy says "nothing is captured until you take a photo" rather than "the feature is off".
- `st.camera_input` cannot be exercised from `AppTest` and needs a real webcam plus `localhost`/HTTPS, so a UI regression test only covers the install-hint branch. Verify the camera path by hand.
- The webcam preview is mirrored with `transform: scaleX(-1)` on `[data-testid="stCameraInput"] video, img` in `inject_css()`. It is display-only: the captured frame sent to the model is unchanged, so do not "fix" the mirror in the image bytes.

## Extras and external APIs

- Do not embed third-party streaming players, whatever the source (this was repeatedly requested and declined): the app only links out via TMDB's watch page and the JustWatch search fallback. Keep it that way.
- `src/extras.py` uses TMDB first when credentials exist. Without credentials it searches Bing video and YouTube concurrently for trailers, uses Wikipedia/Wikidata for cast, and the Wikipedia page-summary endpoint for the plot description. A TMDB key must never be required for the details dialog to work.
- `get_movie_info()` returns cast, plot, and watch data; it includes a trailer only when TMDB supplies one and never runs the slow keyless trailer search. `get_movie_trailer()` is the separate cached keyless search. `get_movie_extras()` still returns `{"cast", "overview", "trailer", "watch", "source"}` for callers that want everything, but the details dialog does not use it. TMDB supplies `overview` when configured; otherwise `_web_info()` resolves the article through Wikidata/`_wikipedia_search()` once, then fetches the cast page and the summary extract in parallel. A missing description renders a caption, never an error.
- The dialog renders `get_movie_info()` with a spinner, then, if no TMDB trailer is available, starts `request_trailer()` in a daemon thread. `request_trailer()` returns `(trailer, ready)` without blocking; while `ready` is false the dialog renders `wait_for_trailer()` (`st.fragment(run_every=1)`), which calls `st.rerun()` when the search finishes so the dialog shows the video. Never call `get_movie_trailer()` from the dialog itself: it blocks the whole fragment for 5-10 seconds. `movie_info_future()` shares an in-flight info lookup, and `prefetch_movie_info()` queues picks on a single low-priority worker, so clicking a "You may like" poster is usually a cache hit.
- `watch` is always a dict (`region`, `available`, `link`, `groups`, `search_url`), built by `_watch_providers()`. `groups` maps `flatrate`/`free`/`ads`/`rent`/`buy` to `[{"name", "logo_url"}]`. The TMDB request already appends `watch/providers`, so there is no extra HTTP call; region comes from `TMDB_WATCH_REGION` (default `US`). With no credentials or no offers, `available` is false and `search_url` is a JustWatch search link — keyless installs must still show that fallback instead of an empty section.
- Trailer, cast, and description results are cached for 6 hours. `_read_response()` enforces wall-clock deadlines because socket timeouts reset per chunk; do not replace it with plain `response.read()`.
- Bing parsing is HTML scraping: each video card's `mmeta` JSON supplies the URL and its `aria-label` supplies the title. If trailers break, inspect `_bing_video_search()` first; the markup, not the scoring, is the fragile part.
- Trailer matching is deliberately strict. `_score_trailer()` requires the movie's own words to appear as one contiguous token run (stop words like "the"/"of" may sit between them), surrounded only by trailer boilerplate (`official`, `trailer`, `hd`, `4k`, …) or the film's own release year; anything else returns `-100`. This is what keeps "Any One of Us" from matching "Us", "Up in the Air" from matching "Up", and "Frozen II" from matching "Frozen". Do not restore the old substring / 60%-of-words matching.
- Bing sometimes answers with a "There are no results for …" page filled with trending videos. `_BING_NO_RESULTS_RE` makes `_bing_video_search()` return `[]` for those pages, and `_best_trailer()` accepts only a result scoring >= 6. Do not reintroduce a "Bing returned something, so stop" guard. `_find_trailer()` now runs Bing and YouTube **concurrently** because YouTube's search endpoint regularly takes 5-10 seconds; making the sources sequential again adds several seconds to every dialog. `_youtube_search()` sets `_YOUTUBE_COOLDOWN_UNTIL` (10 min) after a timeout, and the trailer is cached for 6 hours.
- `data/links.csv` stores IMDb IDs as bare digits. `_normalise_imdb_id()` adds the `tt` prefix and zero-pads; do not assume `tt...` values in the CSV.
- `themoviedb.org` returns 403 to scrapers. Use only `api.themoviedb.org` with a key or bearer token.

## Data and credentials

- The committed CSVs in `data/` are required. `python scripts/download_data.py` re-downloads `movies.csv`, `ratings.csv`, `tags.csv`, and `links.csv`, but does not create `posters.csv`.
- `data/posters.csv` is optional. `python scripts/fetch_posters.py` generates it and requires `TMDB_API_KEY` or `TMDB_API_TOKEN` in `.streamlit/secrets.toml` or the environment. It is incremental; flags are `--workers N`, `--limit N`, and `--refresh`.
- `.streamlit/secrets.toml` is gitignored; use `.streamlit/secrets.toml.example` as the template.

## Behavior to preserve

- Search is case-insensitive substring matching (`regex=False`) with 24 results per page; clicking a poster opens the details dialog.
- The details dialog always shows, in order: the movie card, the plot description (or a fallback caption), a taste-match meter once the session has likes, Trailer, Cast, Where to watch, the watchlist action, and a "You may like" grid of four model picks. Every section needs a graceful fallback.
- Dialogs cannot nest, and a dialog opened inside a widget callback is closed again by the rerun that follows the callback. `show_movie_details()` therefore takes no argument and renders `session_state.details_movie_id`; every poster callback only stores the id, and the dialog is opened once at the bottom of `app.py` during the normal script run. `on_dismiss=close_movie_details` clears the id so a dismissed dialog stays closed. `poster_grid()` and `clickable_movie_card()` wire `on_select` as `st.button(on_click=...)` so the id is set before the rerun — keep that ordering.
- When the dialog swaps to another movie, it scrolls back to the new movie card and keeps a floating "↑ Top" button pinned near the dialog's bottom-right. `scroll_dialog_to_top(movie_id)` uses `st.html(..., unsafe_allow_javascript=True)`, embeds the movie id in the script so the body changes only on a movie swap, and positions the button relative to `[data-testid="stDialog"]`. Keep the id (or some changing part) in the body, and do not call it with a fresh nonce on same-movie reruns, or adding to the watchlist would jump the reader to the top.
- The Home page always shows six clickable "You may like" tiles. With no likes, `may_like_picks()` falls back to `ranking_scores(catalog, [])`, i.e. the quality prior alone (popular, well-rated titles) and the caption says the row becomes personal after liking; with likes it uses the taste blend.
- Keep `README.md` in sync with user-visible behavior.
